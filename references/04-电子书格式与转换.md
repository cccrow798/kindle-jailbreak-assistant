# 04 · 电子书格式与转换

---

## 一、KOReader 格式支持总表

| 扩展名 | KOReader | 说明 |
|--------|----------|------|
| `.txt` `.html` `.md` `.rtf` `.fb2` `.epub` `.epub3` `.cbz` `.cbr` `.djvu` `.docx` `.odt` `.chm` `.xps`；`.png` `.jpg` | ✅ | 直接可读 |
| `.mobi` | ✅ | MOBI6 / KF7 |
| `.azw` | ✅ | 注册表里 mimetype 写作 `application/vnd.amazon.mobi8-ebook` |
| `.pdf` | ✅ | 内置 mupdf；支持裁边、重排 |
| **`.azw3`（KF8）** | ❌ | **不在格式注册表里** |
| **`.kfx`** | ❌ | 不在注册表里，且通常带 DRM |

### 为什么 `.azw3` / `.kfx` "看不见"

不是文件损坏、也不是设置问题，是**后缀根本没登记**：

```lua
-- frontend/apps/filemanager/filemanager.lua:143
file_filter = function(filename) return DocumentRegistry:hasProvider(filename) end,

-- frontend/ui/widget/filechooser.lua:25
show_unsupported = G_reader_settings:readSetting("show_unsupported", false),  -- 默认 false
```

`DocumentRegistry:getProviders()` **纯按文件名后缀匹配**。未登记的扩展名**既不出现在文件浏览器里，也不可能被打开**。
（`.sdr` 目录由 `filechooser.lua` 的 `exclude_dirs` 自动隐藏，不影响列表。）

> 结论：用户说「KOReader 里看不到我 Kindle 的书」，八成就是 `.azw3` / `.kfx` 被过滤掉了。

## 二、`.pdf` 的正确排查口径

**PDF 是支持的，不要急着转换。** 依次做：

1. 确认 `libs/libwrap-mupdf.so`、`libs/libk2pdfopt.so.2` 存在
2. `grep -i mupdf crash.log`：每次启动都成功 `ffi.load`，且无 PDF 相关报错
3. 看该 PDF 的 `.sdr/` 目录里有没有 `metadata.pdf.lua`
   - **没有** → 说明它**从没被 KOReader 打开过**（所以也不可能报过错）
4. 核 PDF 自身：文件头 `%PDF-`、尾部 `%%EOF`、统计实际个数

若都正常，提醒用户区分两处入口：**「书库 / 已读列表」只列打开过的书**，**「文件浏览器」才列全部文件**。并要求用户提供具体报错文字再判断。

## 三、AZW3 → EPUB 标准流程

### 3.1 先体检：哪些能转、哪些绝对不能转

```bash
python scripts/scan_ebooks.py F:/documents     # 只读文件头做识别，不做任何解密
```

判定依据全部在文件头，几秒扫完：

| 字段 | 位置 | 含义 |
|------|------|------|
| `encryption` | PalmDB 记录 0 偏移 12（2 字节） | `0` = 无加密；**`2` = Mobipocket DRM** |
| MOBI 版本 | MOBI 头 +20（4 字节） | `≤6` = MOBI6/KF7；`8` = KF8（即 azw3） |
| 压缩方式 | 记录 0 偏移 0（2 字节） | `1`=无 `2`=PalmDOC `17480`=HUFF/CDIC |
| KFX 特征 | 文件头 | `\xEA D R M I O N \xEE`（DRM Ion 容器） |

### 3.2 政策（必须遵守）

| 情况 | 处理 |
|------|------|
| `encryption != 0`（Mobipocket DRM） | **不转换**。要转必须先解密 = 规避技术保护措施 |
| KFX（文件头 `DRMION`） | **不转换**，同上 |
| `encryption == 0` | ✅ 正常转换 |

**拒绝时的正确话术**：说明技术原因（DRM 保护），并明确告知用户 **这些书在原生阅读器里照常可读**——退出 KOReader 即可；若想在 KOReader 里读同样内容，只能另找无 DRM 的版本。**不要**提供、指引或暗示任何解密工具与做法。

### 3.3 转换

```bash
python scripts/convert_azw3.py F:/documents    # 可反复跑，已合格自动跳过
```

- 工具：**KindleUnpack**（GPL，纯 Python，`tools/kindleunpack/lib/kindleunpack.py`）
- 获取：`https://ghfast.top/https://github.com/kevinhendricks/KindleUnpack/archive/refs/heads/master.zip`
- 产物：`-s` 参数生成 `outdir/mobi8/<输入名>.epub`（EPUB2），**文件名继承输入名**，中文名可直接用
- 性质：**仅解封装**，不涉及任何解密

### 3.4 拷入设备并复核

```bash
python scripts/copy_epub.py       # 只拷台账登记的、体积吻合的
python scripts/verify_epub.py     # 存在性 + 字节数 + MD5 + zip 结构
```

落点：**`F:\documents\`**（Kindle 的 `home_dir` 就是 `/mnt/us/documents`，KOReader 首页即此目录）。

## 四、四个真踩过的坑

### 4.1 KindleUnpack 会把输出目录里的**所有**文件打进 EPUB

复用同一个输出目录 → 每本书都把前面所有书的正文和图片一起打包进去。
实测一本 **0.83 MB 的书被撑到 259 MB**（zip 内 3329 张图 + 828 个 xhtml + 9 个字体）。

**修正**：
- 每本书使用**独立且每次运行全新**的输出目录
- 加**污染检测**：zip 内媒体文件数不应远超 OPF 里的 `<item` 声明数（正常书比值 < 1，污染书可达 1400+）

### 4.2 小书整本可能只生成 1 个 xhtml

别把"正文文件 < 2"当失败。→ 改为按**正文总字节数**判定（阈值 8 KB 足够）。

### 4.3 拷贝被打断会留下截断文件

字节数常是 512 KB 的整数倍，且不是合法 zip；而"同名已存在就跳过"的保护会让它一直留在设备上。
→ 用 `verify_epub.py` 收尾：**不是合法 zip / 字节数对不上就 `rm` 掉重写**。

### 4.4 临时工作区不要放桌面/项目目录

- 放项目目录时，批量删除会触发**安全删除保护**（>50 个文件即拦截），把流程打断
- 放 `%TEMP%` 且**不做任何删除**（每本书一个独立目录）最稳，收尾统一清一次
- 记得清理：这类临时目录很容易残留几十 GB

### 4.5 台账文件

`_converted_ok.json` 只有台账登记**且体积吻合**的文件才允许跳过 / 拷入设备，避免把历史遗留的不合格产物当合格件。
**校验逻辑一改，必须重置台账重转。**

## 五、设备写入规则（FAT32，实测）

| 操作 | 沙箱内 | 沙箱外 |
|------|--------|--------|
| 新建文件 | ✅ | ✅ |
| 覆盖已存在文件 | ❌ | 需**先 `rm` 再写**（`os.replace()` 一定失败） |
| 重命名 / 移动 | ❌ | ✅ |
| 删除 | ❌ | ✅ |

Python 侧：`os.remove(dst)` 之后再 `open(dst,'wb')`；**不要**用 `os.replace()` 或"临时文件 + 改名"。
删除与覆盖都在**沙箱外**执行（`dangerouslyDisableSandbox`）。

## 六、脚本清单

| 脚本 | 作用 |
|------|------|
| `scripts/scan_ebooks.py` | 扫目录，判定格式 / 压缩 / 加密，输出 `_ebook_scan.json` |
| `scripts/convert_azw3.py` | 批量 AZW3→EPUB，三重校验 + 台账 + 独立工作目录 |
| `scripts/copy_epub.py` | 按台账拷入设备，只创建新文件，逐文件 MD5 校验 |
| `scripts/verify_epub.py` | 独立复核设备端，并列出不在台账内的 EPUB |

> 运行脚本请用托管 Python 绝对路径，并设 `PYTHONIOENCODING=utf-8`（中文书名多）。

## 七、转不了的书怎么办

| 书 | 处置 |
|----|------|
| 带 DRM 的 `.azw3` / `.azw` | 留在设备上，原生阅读器可读；KOReader 里读不到是正常现象 |
| `.kfx`（多为购买或 KFX 导入） | 同上 |
| 想两边都能读 | 只能另找**无 DRM** 的同内容版本（如公版书另找 EPUB） |

不要为了让它们在 KOReader 里出现而做任何解密尝试 —— 见 `07-风险与合规.md`。
