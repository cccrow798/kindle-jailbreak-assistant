# 05 · 性能与清理

---

## 一、先纠正一个常见误解

用户说「加了这些书之后变慢了」，**默认的因果假设是错的**。

**结论：文件数量不是性能因素。** KOReader 打开一本书只加载那一本，`documents` 里有 100 本还是 500 本，翻页速度完全一样。

所以不要说「我帮你删点书就不卡了」——那是无效且危险的建议。**按下面的归因链逐条排查。**

---

## 二、性能归因链（按出现频率排序）

| 症状 | 真凶 | 证据 / 判据 | 处置 |
|------|------|-------------|------|
| **点字查词半天没反应、拉顶部栏迟滞** | **词典启用过多**（每本都跑一遍 sdcv，且 `dismissablePopen` 退化为阻塞 `io.popen` 卡住主线程） | `crash.log` 里 `WARN unwrapped dismissablePopen(), falling back to blocking io.popen()`，出现次数与卡顿时刻吻合 | 精简到 3~4 本（`fix_dict_lag.py`） |
| 某本书**第一次**打开慢一两秒 | KOReader 生成排版缓存 | `koreader/cache/cr3cache` 体积增长 | 正常，第二次就好 |
| 首进**文件浏览器**慢 | coverbrowser 提取封面 | 一次性 | 正常，之后走缓存 |
| 写入慢 / 拷书卡 | FAT32 大目录 + 剩余空间紧张 | 与「阅读」无关 | 腾空间即可 |
| 翻页本身发涩 | 通常不是 KOReader | 对比原生阅读器 | 检查是否开了省电/刷新模式 |

**排查顺序建议**：先看 `crash.log` 里 `dismissablePopen` 的次数 → 再数启用的词典本数 → 再看缓存目录体积。

> 词典查询为什么是主线程杀手：`frontend/ui/trapper.lua` 的 `dismissablePopen` 在协程不可用时**退化为阻塞 `io.popen`**；全树只有 `readerdictionary.lua` 调用它。

---

## 三、什么绝对不能删

| 对象 | 原因 |
|------|------|
| **任何非空 `.sdr` 目录** | 里面是**阅读位置 / 标注 / X-Ray / 生词本**。`metadata.*.lua` 是 KOReader 的，`*.mbp1` `*.mbs` `*.phl` `*.asc` 是原生 Kindle 的。删了永久丢失（电脑备份里通常没有） |
| `documents/*.sh` | KPM 的 **scriptlet 启动器**，图标 base64 内嵌在脚本里；删了原生书库就没有 KOReader 入口 |
| `system/` `voice/`、`koreader/` 的二进制与 `libs/` | 系统与应用本体 |
| `koreader/data/dict/` 中**正在启用**的词典 | 删了查词就废 |
| `libkh/` `kmc/` `apps/` `mesquito/` | 越狱与包管理本体 |

---

## 四、可以删（真实垃圾，逐条验证过）

| 类别 | 特征 | 判定方法 |
|------|------|----------|
| 空 `.sdr` 目录 | 书改名/删除后留下的空壳 | `find <doc> -maxdepth 1 -type d -name "*.sdr" -empty`（`-empty` 只匹配**完全空**的） |
| `*.kfx.sd` | 0 字节，原生系统的 SD 标记残留 | 后缀匹配 + 大小为 0 |
| `.fuse_hidden*` | 删除未完成的残片（Linux FUSE 特性） | 文件名前缀 |
| `*.tmp.sa.decompressed` | 解压临时残留 | 子串匹配 |
| `*crash*.tgz` | KPM 主程序崩溃转储 | 名字含 `KPPMainApp` + `crash`，体积常几 MB |
| 已禁用的词典目录 | 在 `settings.reader.lua` 的 `dicts_disabled` 里 | 删前确认源包在电脑上 |
| 冗余书籍格式 | 例如已转好 EPUB 后、只服务原生阅读器的 `.azw3` | **必须先确认电脑备份逐文件 MD5 一致**，且要提醒用户「原生阅读器上这些书会消失」 |

> 转换后的 `.epub` 与原始 `.azw3` **不算重复冗余**：前者给 KOReader，后者给原生阅读器（原生可查词典、有生词本）。
> **要删哪一边，必须先问用户平时在哪读。**

---

## 五、删之前必须做的三件事

1. **列清单 + 白名单**：脚本只允许删除落在 `<盘>:/documents` 和 `<盘>:/koreader/data/dict` **之内**的路径，越界直接中止。
2. **备份核验**：对要删的书，逐个 **MD5** 比对电脑备份（不要只看文件名和大小）。
3. **在用记录排除**：把所有含 `metadata.*.lua` / `*.mbp1` 的 `.sdr` 收集出来，断言它们**不在**删除清单内。
   - 这一步要真的去 `grep` 清单文件，**不能只看脚本输出**（踩过坑：脚本参数写反导致"校验通过"是假的）。

---

## 六、执行

```bash
python scripts/clean_device.py F:          # 预览（默认就是预览，不删任何东西）
python scripts/clean_device.py F: --go     # 确认无误后执行
```

> ⚠️ **删除必须在沙箱外执行**（`dangerouslyDisableSandbox`）。
> 沙箱下删除会走"回收站"逻辑，而 FAT32 分区没有回收站，结果是 `[WinError 5] 拒绝访问`。
> 同理，**覆盖 / 改名在沙箱下也会失败**，只有「新建」可以。

### 清理前的告知义务

执行前必须向用户说明：

- 设备端**没有回收站，删了不可逆**
- 删掉的批次、数量、体积，以及"哪些书之后在原生阅读器里不再出现"
- 清单会另存为 `_清理清单_YYYYMMDD.txt`（**存在电脑侧**，不要只放设备上）

用户若明确表示"不用备份"，仍应在动手前**核实电脑侧备份确实存在**，再执行。

---

## 七、收尾

- 改过配置就顺手备份：`settings.reader.lua`、每本书的 `metadata.*.lua`
- 删完提醒用户：**重启 KOReader**（词典与文件列表都在启动时扫描）
- 清理临时工作区（AZW3 转换的中间产物很容易残留几十 GB）

## 八、典型判读数据（PW3 实测参考）

| 项目 | 清理前 | 清理后 |
|------|--------|--------|
| 设备剩余空间 | 1.1 GB | **1.8 GB** |
| `documents\` | 969 MB / 362 条目 | 530 MB / 238 条目 |
| `.sdr` 目录 | 193（含 62 个空壳） | 131（全部在用） |
| 词典 | 9 本 / 589 MB | **4 本 / 268 MB** |
| 书 | 57 azw3 + 55 epub + 25 kfx + … | 55 epub + 25 kfx + 7 mobi + 14 txt + 2 azw + 1 pdf |

清理总量 **750 MB**；复核结果 **0 残留**，在用的阅读记录全部安然。
