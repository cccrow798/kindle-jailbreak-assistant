# 06 · 排错与 FAQ

按**症状**检索。每条给出「先查什么 → 再做」。

---

## A. 越狱阶段

### A1 浏览器打不开触发页

1. 确认 Wi-Fi 已连且能上网（浏览器随便开一个站点试试）
2. 确认地址没输错（WinterBreak2 是 `https://penguins184.xyz/wb2`，注意 `https`）
3. 重启 Kindle 再试（浏览器缓存/进程卡住很常见）
4. 仍不行 → 回官方向导复核方法是否选对（固件是否已超出该方法的区间）

### A2 点了按钮没反应

1. 确认 `F:\winterbreak2\` 文件夹**存在且完整**（不要只拷了里面的文件）
2. 确认拷完后**安全弹出**过、且没有拔线中断过拷贝
3. 重新拷一次（用校验过的压缩包重新解压）

### A3 屏幕出现「应用程序错误」弹窗

**这是正常的**。越狱脚本自带提示：`Error dialog is fine — Just press close and keep waiting!`
点关闭，继续等，不要重复触发。

### A4 屏幕好像卡住了

越狱阶段写盘很慢，界面看起来像死机是正常的。**等待时间给足**（若干分钟）。
只有等待远超预期才考虑长按电源键 40 秒强制重启，然后重新走一遍。

### A5 重启后 JAILBROKEN 不见了 / `;log` 没输出

越狱**未持久化**：
1. 确认根目录没有残留的 `update*.bin`（有的话越狱可能被更新顶掉）
2. 打一次热修复（见 `02-越狱实操.md` 第四节）
3. 再重启复验

## B. KOReader 安装与启动

### B1 图书馆里没有 KOReader 图标

1. `documents/` 下确认存在 `KOReader.sh`
2. **重启一次 Kindle**（scriptlet 需要重新索引才会变成"书"）
3. 仍无 → 搜索框跑 `;kpm update`
4. 仍无 → 用搜索框 `;kpm launch koreader` 直接启动，确认程序本体是好的

### B2 `;kpm` / `;log` 没反应

越狱持久化失效 → 见 A5。

### B3 KOReader 启动后黑屏 / 闪退

1. 查 `F:\koreader\crash.log` 尾部
2. 确认装的包**平台后缀正确**（`kindlepw2` vs `kindlehf`）
3. 确认**架构匹配**（5.16.3 起 hard-float；5.16.2.1.1 及以前 soft-float）
4. 重新离线装一次（`install_kpm_package.py` + `verify_install.py`）

### B4 装完校验不过（有文件缺失 / SHA256 不一致）

1. 大概率是**写入被中断**（前台超时被打断）→ 用后台重跑安装
2. 检查剩余空间是否足够（KOReader 约 85 MB，安装期间建议留 ≥ 220 MB）
3. 检查设备盘是否有 `FAT` 层的坏簇（换根数据线/换个 USB 口）
4. 重跑 `install_kpm_package.py`（幂等，会补齐），再 `verify_install.py`

## C. 书籍与格式

### C1 KOReader 里看不到某些书

**九成是 `.azw3` / `.kfx` 被格式过滤**（后缀未登记在 KOReader 注册表里）。
→ 见 `04-电子书格式与转换.md`。

### C2 打开某本书报错

先看该书 `.sdr/` 下有没有 `metadata.*.lua`：

- **没有** → 说明**从未成功打开过**，所以没有历史报错可查，本次才是第一次
- **有** → 对比 `crash.log` 里同一时间点的记录

### C3 PDF 看不到

PDF **是支持的**。区分「**书库/已读列表**」（只列打开过的）与「**文件浏览器**」（列全部文件）。
若确实报错，索取报错原文再判断。详见 `references/04` 第二节。

### C4 转换后 EPUB 体积异常大

**KindleUnpack 复用了同一个输出目录**，把其他书的内容一起打包了。
→ 每本书必须用独立且全新的输出目录；脚本已内置污染检测（媒体数 / OPF 声明数比值 > 1 即告警，污染书可达 1400+）。

### C5 设备上出现截断的 EPUB

拷贝被中断。字节数常是 512 KB 的整数倍且不是合法 zip。
→ 用 `verify_epub.py` 查出，`rm` 掉重写。

### C6 带 DRM 的书转不了

**这是正确行为**。`encryption=2`（Mobipocket DRM）或 KFX（`DRMION` 头）**不做转换**。
告知用户：这些书在**原生阅读器**里照常可读；KOReader 里想读同样内容只能另找无 DRM 版本。
**不要**提供任何解密途径。见 `07-风险与合规.md`。

## D. 性能

### D1 点字查词半天没反应 / 拉顶部栏迟滞

词典启用太多。
1. `crash.log` 里搜 `dismissablePopen`，出现次数应与卡顿时刻吻合
2. 数一下启用的词典本数（`settings.reader.lua` 的 `dicts_disabled`）
3. **同时检查每本书 `.sdr/metadata.*.lua` 里的 `preferred_dictionaries`**——它会覆盖全局禁用
4. `fix_dict_lag.py` 精简到 3~4 本

### D2 加了书之后变慢

**文件数量不是性能因素**（打开一本书只加载一本）。回到 `05-性能与清理.md` 的归因链逐条排。

### D3 首次打开某本书慢

生成排版缓存（`koreader/cache/cr3cache`），一次性，第二次就快。

### D4 首进文件浏览器慢

coverbrowser 提取封面，一次性。

### D5 设备整体卡死

长按电源键 **40 秒**强制重启。

## E. 词典

### E1 很多英文单词查不到

英语词典词条量不足 → 换大词库（如 ECDICT，数百万词条）。
变形词（`running` / `went`）查不到属词典缺词形表，换带 `.syn` 或变形表的版本。

### E2 装了词典但列表里没有

1. 确认格式是 **StarDict**（`.ifo` + `.idx` + `.dict`/`.dict.dz`），Kindle 原生 `.mobi`/`.azw` 词典**不支持**
2. 确认放在 `F:\koreader\data\dict\` 之内（含子目录都可以）
3. **重启 KOReader**（词典是启动时扫描的）

### E3 能否把 Kindle 原生词典转成 KOReader 可用格式

**通常不能**。原生词典多为 `.mobi`/`.azw` 且**带 DRM**（`encryption=2`），转换需先解密 → 属于规避技术保护措施，**不做**。
替代方案：装自由许可的等价大词库（英汉用 ECDICT，英英用公开的 reader.dict 系、GCIDE 等）。

## F. 通用

### F1 设备上删文件报 `WinError 5 拒绝访问`

两个可能：
1. **在沙箱内删除** → 改用沙箱外执行
2. **试图覆盖 / 改名已存在的文件** → FAT32 上先 `rm` 再写，不要用 `os.replace()`

### F2 拷大文件时中断

前台命令超时被 SIGTERM 打断。→ 用后台执行，并在结束后用校验脚本复核设备端。

### F3 想恢复出厂设置

**不要**。越狱会失效、书库会清空。要重置请先向用户说明后果并取得明确同意，且明确指出这会丢失越狱。

### F4 不确定某操作是否安全

按这个顺序判断：

1. 它是否删改 `libkh` / `kmc` / `koreader` / `documents/*.sh` / 非空 `.sdr`？→ **不要做**
2. 它是否需要解密 DRM？→ **不要做**
3. 它是否不可逆且用户没明确同意？→ **先问**
4. 都不涉及 → 备份后执行
